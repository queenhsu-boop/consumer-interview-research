# 分阶段研究协议

只读取和执行用户当前需要的阶段。以下产物可合并在一个文档中；规模小时不强制多文件。

## A. 研究设计与采样

将业务决策写成“团队要决定什么，研究能减少什么不确定性”。区分理解行为的探索、比较概念的评估、实际任务的可用性测试。缺少会改变方法的品类/人群/决策信息时集中询问；其余缺项标假设并继续草拟。

形成研究问题 → 需要的经历 → 招募维度 → 取证方式的对应表。消费品优先考虑：近期购买/使用经历、品牌保持或切换、渠道与规格、家庭角色、使用情境。收入、年龄等只在与问题相关时分层。不要只招愿意抱怨产品的人，也不要默认活跃/流失/未用三个分组适合所有品类。

筛选问卷应含：
- 最近一次亲自参与购买或使用的时间、品类、角色、渠道等行为问题；
- 与研究问题有关的纳入、排除和分组规则及理由；
- 研究相关职业/专业受访经历等按项目风险处理，不机械排除；
- 可访问性、语言、可参加形式；单独处理录音或观察同意。
不提前透露目标痛点或理想回答。区分确认资格的封闭题与探索行为的开放题。预算/名额给出可调整的初始方案和依据，不许诺某个人数必定饱和。根据关键情境缺口、新解释和相反案例决定补样；停止原因可以是证据足够支撑当前有限决策，也可以是预算用尽，二者必须分开。

输出：研究简报、采样矩阵、可执行筛选问卷和研究局限。区分计划与实际覆盖；记录实际招募渠道、纳入者、已知拒访/失访和未覆盖情境。记录仅限必要的去标识汇总，不追索拒访者的额外信息。单一品牌社群、平台或近期购买门槛可能遗漏线下、低频或流失者；报告这些限制，不把矩阵设计本身当作已覆盖。研究资格是对项目的匹配，不是参与者优劣评分。

## B. 提纲、观察与试访

用合适的时长覆盖：
开场与同意 → 角色热身 → 最近一次购买与选择 → 最近一次实际使用 → 补货/续购/换牌 → 未解释差异 → 收尾。
不是每位参与者都经历全部环节；没有参与的部分跳过并标记，不让其猜家人想法。

消费品的可选追问点：触发时刻、真实考虑和放弃的替代品、谁决定/付款/使用、渠道、规格、实际支付、促销、存放、开封、取用、用量、清理、处置和再次购买。按问题选用，不逐项机械盘问。

先让参与者自由讲述，再中性追问“当时做了什么”“接下来呢”“怎么判断的”“能讲一次具体经历吗”。抱怨后追问实际行动；不要将满意度、未来意愿当行为。出现矛盾先核对不同事件/情境，不先判参与者不诚实。自发提及与主持人提示后的回答分别标注。

可邀请展示现有包装、订单、存放或使用动作，先取得同意并避免记录无关个人信息；明确是真实自然行为还是访谈现场演示，后者可能受观察影响。概念/包装测试放在未经提示的行为回顾之后，记录刺激物版本、呈现顺序及暴露情况；比较多个方案需考虑顺序与品牌提示偏差，不能从访谈偏好推出销量。日记研究、居家试用和感官盲测涉及额外设计；本技能可起草方案，不能冒充已实施或验证。

每个主题保留主问题、中性追问、适用分支、软时间预算、优先级。逐题检查预设原因、诱导评价、双重问题、只问理想未来；行政确认允许封闭题。安排真实口头预演/小范围试访，记录题目修订；没有做就保留待完成状态。

## C. 材料接收与来源

给每人、场次、文档/录音及事件稳定标识，保存事件日期及访谈日期（未知即未知），区分完整逐字稿、节选、观察笔记、转述、合成材料。事件表注明产品/规格、时间和角色；只有原材料确认关联的购买、使用、补货事件才连成旅程，关联未知就分开。重复参与或同一家庭建立关联；跨波次和版本变化另记，不盲目合并。

编号在合并材料后仍须唯一。例如 P01-S01-T01 与 P02-S01-T01 是两条记录，P01 的复访使用 P01-S02；事件 ID 同样带参与者/来源前缀，不让不同人的 B01/U01 混在一起。多人同场时保留共同场次及各自说话人。保留原导出编号和来源映射，重名只增加内部唯一键，不改原文；旧编号是否代表同人或同场不明时先核对，不能靠编号相同自动合并。

长材料按完整案例分批处理，维护已读/未读清单与可回查原文的编码表。后续比较返回原文核对关键差异，不只从上一轮摘要继续压缩；未读部分不得隐含为已覆盖。

资料不足时仍可做局部分析并说明范围，不补造。逐字稿由音频得到时，文本校验无法发现转录本身的错听。关键引文对照可用录音/原稿。不能将 AI 对图片/音频的猜测当已确认内容。

短材料可用带位置的 Markdown 台账；逐字引文交付使用下面 JSON 接口做确定性核验。来源 JSON 是从原始材料忠实整理的快照，需保留原文件；程序不验证快照是否忠实，也不校验 locator 的真实性。

source.json：
```json
{
  "turns": [
    {"id":"S1-T02","participant_id":"P01","speaker":"participant","verbatim":true,
     "locator":"P01.txt:L12","text":"上次没货，我买了另一款。"}
  ]
}
```
id 在整个来源文件中唯一。speaker 可为 participant/interviewer/observer/other。不逐字的记录 verbatim=false，只用于带来源的摘要，不作为逐字引文。locator 应指向原文行段或录音时间，不凭空生成。

evidence.json：
```json
{
  "source_sha256":"填写对 source.json 原始字节计算的 SHA-256",
  "quotes":[
    {"id":"Q01","participant_id":"P01","turn_id":"S1-T02",
     "start":0,"end":12,"quote":"上次没货，我买了另一款。"}
  ]
}
```
start/end 为 Python 字符串的字符索引，左闭右开（不是 UTF-8 字节数）。连续原文精确匹配，不折叠空白、不改标点。多个不连续片段建多个 quote ID，展示省略时分别核验并审查上下文，不拼成伪造整句。来源更正后保存新版本，重新核验受影响结论；hash 只能检查文件一致性，不能证明真实性。

运行命令中的脚本路径需根据本 skill 的实际目录解析；不要假定工作目录在 skill 内。脚本无网络调用，不修改输入；标准输出给出匹配或错误，退出码 0=所列引文通过，1=归属/范围/hash不匹配，2=文件/结构错误。空台账不会通过。无逐字引文的研究不必制造引文来满足程序。

## D. 逐案分析与跨案比较

先用事件表还原每人的触发、候选、选择、使用、结果及后来行动，再提取一个观察一行的台账：
观察 ID｜参与者/场次｜位置或 quote ID｜原话/观察摘要｜亲历/转述/观察｜自发/提示｜事实自述/解释/假设｜情境。

初始编码可以来自研究问题，但须保留意外发现。代码要有定义、纳入/排除说明和例子；比较并修订后记录版本。含混处返回原文；多人编码时讨论解释差异，不以“大家同意”或某个一致率代替效度。

建立主题 × 案例矩阵：每格写支持、限制、反证、未问、未提及、不记得或不适用，可并存不同情境。研究中自述也可能有回忆误差与社会期许偏差；不要把所有观察都称为客观事实。

每条发现交付：
- 在什么人/情境中观察到什么；哪些证据支持，哪些反证限定它；
- 解释是什么，和别的解释相比依据何在；动机不明可不写 because；
- 支持与反证的独立参与者/家庭 ID；实际问题覆盖及样本选择局限；
- 证据的直接性、完整性、情境一致性和不确定性；频次只是描述维度；
- 对当前决策意味着什么，下一步什么证据可能推翻或收窄它。

不强求低频现象只放附录。严重障碍或独特细分情境可以单列发现，但明确单例与适用条件。避免用有偏筛选样本“证明”同一筛选条件普遍；不按表述次数排机会，不强制输出固定数量主题或画像。

### D1. 从现象到可改变条件

仅对会影响当前决策的重要现象使用以下指引，可并入现有分析，不要求为每条材料新增表格。目标是找到值得取证或尝试改变的条件，不追求一个包办所有情境的最根本原因。

1. **现象**：写清在什么情境下发生了什么、先后顺序、实际后果及来源。先描述行为或体验；将参与者给出的原因单列为自述，不把它直接写成已证实的机制。
2. **候选解释**：优先从材料线索与跨案差异提出解释，逐项注明支持、限制及未知；另行提出的探索性假设标明证据缺口。不同解释可以并存，不凑固定数量，不把同一解释换词充数。无法提出有依据的解释时，保留未知并指出缺什么。
3. **区分证据**：对会导向不同动作的解释，说明若成立还应出现什么、什么结果会削弱它，并指出它们对同一事件或条件变化的预期有何不同。优先回查已有记录和相反案例，再选择最可能改变决策、取证负担可接受的一项观察、中性追问或比较。若同一回答能同时支持所有解释，它不能单独区分这些解释；未问或未记录也不算反证。
4. **可改变条件**：有条件地写出谁在何时改变什么、预期改善哪个可观察结果，以及什么结果或新增负担应使方案调整或停止。解释未确认时，交付待验证动作，不写成有效方案。若不同解释指向同一个低成本、可逆动作，可以先验证动作效果，但不能据此宣称某个解释已被证明；多个条件同时改变时只评价整体方案。没有可控条件或证据不足时，保留问题并安排补证或交接，不强行产出设计。

简短记录可用：现象及出处｜候选解释与证据状态｜能区分解释的证据及取证办法｜可改变条件与预期结果｜反证或停止条件｜当前决定。仅保留对本次决策有用的字段；这段指引不把定性线索升级为因果证明。

方法示例（假设材料，不是真实研究发现）：记录仅显示一位顾客要求半份原味、半份拌，以下均为待核候选，不能凭这条要求确认。

| 候选解释 | 需要区分的实际经历 | 若获得支持可试的条件 |
|---|---|---|
| 同餐者对辣度的要求不同 | 两份最后分别给谁吃、如何调味；只有一人吃时是否仍这样分份 | 门店按食用者分份调味，检查是否减少额外分餐或有人不能吃的情况 |
| 原味用于后续回锅 | 原味是否实际下锅、何时怎样处理；没有再加工安排时是否仍这样分份 | 为回锅部分保留原味，检查是否减少后续处理困难 |

两种用途可同时存在。若材料没有交代实际吃法，下一步先还原两份的使用过程，不直接询问顾客是否追求自主感，也不提前决定增加所有调味选项。

## E. 可选 JTBD 与决策交付

当现有证据能说明情境、希望取得的进展、实际替代方案与取舍时，整理 JTBD；功能/情绪/社会三个维度可以为空，不能补全模板而猜测。仅有态度或零碎引文时只写待验证 job 假设。JTBD 不反过来筛掉不合模板的观察。

机会排序解释受影响情境、后果、现有替代、证据强弱和业务相关性，不以小样本频次构造市场规模或伪精确 ROI。分别写发现、解释、方案和验证计划。例如“瓶口难清理”不自动推出“消费者愿为新瓶多付钱”。

最终报告与证据台账逐条交叉检查，回查所有将影响决策的主张及关键反例，保留接受/修改/搁置理由。AI 自审或多 agent 同意不等于独立人类研究验证。

能力边界：可支持提纲、编码、差异发现、解释假设和下一轮研究。不能独自完成真实招募、保证主持质量、证明因果/总体规模/支付分布、认证产品功效；不能用虚构访谈给真项目补样。真实现场观察、复杂感官试验、未成年人或敏感人群研究需项目相应专业能力与安排。
